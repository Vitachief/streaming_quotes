# Streaming Quotes

Система стриминга биржевых котировок по TCP/UDP с поддержкой фильтрации тикеров и keep-alive (PING).

## Архитектура проекта

Один Cargo-пакет, разделённый на библиотеку и два бинарных файла:

- `src/lib.rs` — ядро: общие типы (`StockQuote`), протокол (`Command`, парсинг), работа с файлами (`tickers`).
- `src/bin/server.rs` — сервер: TCP-listener, генератор котировок (отдельный поток), UDP-рассылка (поток на подписчика), мониторинг PING (отдельный поток).
- `src/bin/client.rs` — клиент: TCP-подписка, приём UDP-датаграмм в основном потоке, отправка PING в фоновом потоке.

## Сборка и тестирование

```bash
# Сборка без ошибок
cargo build

# Запуск юнит-тестов (парсинг, round-trip, загрузка тикеров, фильтрация)
cargo test
```

## Команды запуска

1. **Запуск сервера**
   Аргументы: `<tcp_port> <ping_udp_port> <путь_к_файлу_тикеров>`
   ```bash
   cargo run --bin server -- 7878 7879 assets/tickers.txt
   ```

2. **Запуск клиента**
   Аргументы: `<адрес_tcp_сервера> <адрес_ping_сервера> <локальный_udp_порт_клиента> <путь_к_файлу_тикеров>`
   ```bash
   cargo run --bin client -- 127.0.0.1:7878 127.0.0.1:7879 9000 assets/tickers.txt
   ```

## Спецификация протокола

### TCP (управление)

- **Запрос клиента:** `STREAM <udp_addr> <ticker1,ticker2,...>\n`
  Пример: `STREAM 127.0.0.1:9000 AAPL,TSLA\n`
- **Ответ сервера (успех):** `OK\n`
- **Ответ сервера (ошибка):** `ERR <причина>\n`
  Возможные причины: `Unknown command`, `Invalid UDP address format`, `Empty tickers list`, `No valid tickers provided`.

### UDP (данные и keep-alive)

- **Котировка:** `<ticker>|<price>|<volume>|<timestamp_ms>\n`
  Пример: `AAPL|150.5|1000|1690000000000\n`
- **Keep-alive (клиент → сервер):** `PING\n` — отправляется каждые ~2 секунды.
- **Тайм-аут:** если сервер не получает `PING` от клиента более 10 секунд, подписка аннулируется, а поток рассылки завершается.

## Прогон тестов вручную

Все команды выполняются из корня проекта.

### Предварительная подготовка

```bash
cargo build
cargo test
```

### Шаг 1. Базовый сценарий: успешная подписка и поток котировок

1. В первом терминале запустите сервер:
   ```bash
   cargo run --bin server -- 7878 7879 assets/tickers.txt
   ```
   Ожидаемый вывод:
   ```
   [Server] PING listener started on 0.0.0.0:7879
   [Server] TCP listener started on 0.0.0.0:7878
   ```

2. Во втором терминале запустите клиента:
   ```bash
   cargo run --bin client -- 127.0.0.1:7878 127.0.0.1:7879 9000 assets/tickers.txt
   ```
   Ожидаемый результат:
   - Клиент печатает `[Client] Subscribed successfully. Receiving quotes on 127.0.0.1:9000...`
   - Далее непрерывно выводятся строки вида:
     ```
     AAPL     | $150.50   | Vol: 1234  | TS: 1728400000000
     MSFT     | $310.20   | Vol: 2500  | TS: 1728400000500
     TSLA     | $245.10   | Vol: 4100  | TS: 1728400001000
     ```

### Шаг 2. Проверка обработки неверной команды TCP

1. Сервер уже запущен.
2. В третьем терминале подключитесь через `nc`:
   ```bash
   nc 127.0.0.1 7878
   ```
3. Введите некорректные команды и нажмите Enter:
   - `SUBSCRIBE 127.0.0.1:9000 AAPL` → `ERR Unknown command. Expected STREAM`
   - `STREAM not_an_address AAPL` → `ERR Invalid UDP address format`
   - `STREAM 127.0.0.1:9000` → `ERR Invalid STREAM format. Expected: STREAM <udp_addr> <tickers>`
   - `STREAM 127.0.0.1:9000 ` → `ERR Empty tickers list`

### Шаг 3. Отклонение неизвестных тикеров

1. Создайте файл с несуществующим тикером:
   ```bash
   echo "FAKE" > /tmp/fake_tickers.txt
   ```
2. Запустите клиента с этим файлом на другом UDP-порту:
   ```bash
   cargo run --bin client -- 127.0.0.1:7878 127.0.0.1:7879 9001 /tmp/fake_tickers.txt
   ```
   Ожидаемый результат: клиент печатает `[Client] Server rejected subscription: ERR No valid tickers provided` и завершает работу. UDP-стрим на сервере не открывается.

### Шаг 4. Keep-alive: остановка стрима при тайм-ауте PING

1. Запустите сервер и клиента, как в Шаге 1. Убедитесь, что котировки идут.
2. Резко остановите клиента комбинацией `Ctrl+C`.
3. Подождите ~10 секунд.
   Ожидаемый результат:
   - Сервер продолжает работать и не падает.
   - Поток рассылки для остановленного клиента завершается автоматически (через `mpsc` drop).
   - Утечек потоков не происходит — при повторном запуске клиента на том же порту 9000 подписка восстанавливается и котировки снова идут.

### Шаг 5. Параллельная работа нескольких клиентов

1. Сервер запущен.
2. Запустите клиент 1 на UDP-порту 9000:
   ```bash
   cargo run --bin client -- 127.0.0.1:7878 127.0.0.1:7879 9000 assets/tickers.txt
   ```
3. В новом терминале запустите клиент 2 на UDP-порту 9001:
   ```bash
   cargo run --bin client -- 127.0.0.1:7878 127.0.0.1:7879 9001 assets/tickers.txt
   ```
   Ожидаемый результат: оба клиента независимо получают котировки. Сервер корректно маршрутизирует данные через отдельные `mpsc`-каналы и UDP-сокеты.

### Шаг 6. Негативные сценарии

- Пустой файл тикеров: `echo "" > /tmp/empty.txt` → клиент сообщает об ошибке чтения.
- Несуществующий файл: `cargo run --bin client -- ... /tmp/no_such_file.txt` → понятная ошибка `Failed to load tickers`.
- Некорректный адрес в STREAM через `nc`: `STREAM not_an_address AAPL` → ответ `ERR Invalid UDP address format`.
